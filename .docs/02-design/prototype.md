# NaraNews — Prototype (W5 Design Draft)

## Live click-through prototype
<a href="https://nara-news-digest.lovable.app/" target="_blank" rel="noopener noreferrer">https://nara-news-digest.lovable.app/</a>

Built by the team in Lovable. This supersedes the static wireframe below — it's a real, interactive click-through
covering setup and all three delivery journeys, and it already reflects the compliance requirements visually, not
just the features:

- **Setup to digest** — topic-priority picker (Politics, Economy, Bangkok, Weather, Society, Travel, Health,
  Sport), delivery-schedule step. Feeds F1's aggregation and F5's channel choice.
- **Journey A — the popup digest [F1, F2]** — toolbar icon → scrollable list, each row a source, category,
  timestamp, and one-line summary; click opens the source article. "5 Thai sources aggregated" footer.
- **Journey B — email digest [F3]** — same digest content by email when away from Chrome, with the LR1/LR3/LR4
  language made visible in the UI itself: *"Sent to a verified address only, used for this digest and nothing
  else. Consent recorded on 2 Sep 2026 · Unsubscribe any time."*
- **Journey C — idle notification [F5]** — a single system notification surfaces the newest headline after a
  quiet stretch; clicking it opens the popup on that story. The opt-in screen states the LR5 purpose limit
  directly: *"Used only to deliver this digest / Your channel choice is stored for delivery only."*

This is the prototype to reference for the W5 submission — it's more complete and more honest about the
compliance requirements than the earlier static wireframe it replaces.
